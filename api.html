Base URL and authentication

Requests use https://realcitycommerce.com/v1/storefront or the API origin supplied by your store owner. Include the full publishable key in X-RCM-Key. The order-list operation requires a server key.

Shell
curl "https://realcitycommerce.com/v1/storefront/products?limit=10" \
  -H "X-RCM-Key: rcm_pk_YOUR_WEBSITE_KEY"

Send Content-Type: application/json with request bodies. Amounts ending in Cents are integers. Resolve image paths against the API origin. Path parameters in braces must be replaced with URL-encoded values.

Store and catalog

GET /store

Returns the connected store’s id, slug, name, currency, email and phone.

GET /products

Returns { products, total }. Optional query fields include collection (slug), q, tag, sort (newest, price_asc, price_desc, title), limit, offset and lang (en or fr). Use variant IDs, integer-cent prices and stock availability in your product interface.

GET /products/{slug}

Returns { product } for an Active product in the store. Accepts lang. A missing or unpublished slug returns 404.

GET /collections

Returns { collections }. Each includes its slug, title, description, image and active product count.

GET /availability

Returns salesEnabled, paused, testMode, message, and stripe. Use this to determine whether card sales are ready. A non-null stripe may supply a publishable key for supported custom payment integrations.

Checkout and orders

POST /checkout

Requires items with variantId and quantity, plus absolute successUrl and cancelUrl. customerEmail is optional. Returns 201 with orderId, number, reference, hosted url, and mock.

GET / POST /checkout/{orderId}/confirm

Returns paid, status, reference, paymentMethod, paymentLabel, instructions, totalCents, and currency. Use the order ID from checkout. Some manual payments remain pending.

POST /orders

Submits an order or quote in a quote-enabled integration. Send items and at least one of email or contactPhone. Also accepts contactName, contactAddress, notes, fulfilment (pickup or delivery), and paymentMethod (card or terms). Returns 201 with { order }. Use hosted checkout for standard online payment.

POST /orders/lookup

Send { reference, contact }. The contact must match the phone or email on the order. Returns { order }, including shipments and tracking when present.

GET /orders

Requires the server key. Returns { orders } with up to the 100 most recent orders. Keep this operation and the returned customer information on your server.

Showcases and pop-ups

GET /collaborations

Returns { enabled, collaborations }. Entries contain id, title, company, image, and section. Disabled showcases return an empty array. Sort order is newest first.

GET /popups

Returns { enabled, popups } with published current or upcoming events when enabled. Each event includes its name, dates, location and display details.

Contact and chat

POST /contact

Send name, email, and message. An order reference is optional. A successful submission returns { ok: true }.

GET /chat

Returns { store: { name } } for the connected store.

POST /chat/conversations

Send email and message with optional name and orderReference. Returns the customer’s conversation, message, access token, and hosted chat URL.

GET /chat/conversations/{id}

Use the website key and the conversation access token in X-RCM-Chat-Token. Optional after returns only newer messages. Optional peek=1 checks without marking the conversation seen.

POST /chat/conversations/{id}/messages

Use the website key and conversation token. Send { message }. Returns the saved message with 201.

Errors and testing

Errors generally return a JSON object with an error message. Check the HTTP status before reading a success payload.

  • 400 means a field was missing or invalid. Check the request shape and show actionable feedback.
  • 401 means the expected key or token was missing, invalid, or revoked.
  • 403 means the operation needs different credentials or access is restricted.
  • 404 means the item is missing, unpublished, or unavailable to the request.
  • 429 means too many requests. Wait before retrying.
  • 5xx means the service could not complete the request. A retry is safest for GET operations. Check for an existing order before submitting a failed write again.

Test with a development or test store, sample orders and test payment methods. Account management, catalog editing and payment-provider setup are available in the owner dashboard.
